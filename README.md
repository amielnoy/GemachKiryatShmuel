# גמ"ח מזון — ניהול חלוקה שבועית

אפליקציית React + TypeScript לניהול חלוקת חבילות מזון שבועית, בנויה ל-Vercel.

- **רכז** — מנהל משפחות, מובילים ושיבוץ, ורואה את התמונה המלאה.
- **מוביל** — נכנס, בוחר את שמו פעם אחת, ורואה מסך אחד עם 2–4 המשפחות שלו. נגיעה בשורה מסמנת "נמסר".
- עובד בדפדפן במחשב, באנדרואיד וב-iOS, וניתן להתקנה למסך הבית (PWA).

---

## הפעלה מקומית

```bash
npm install
npm run dev
```

האפליקציה תעלה על `http://localhost:5173`. בלי משתני סביבה היא עובדת מיד, אבל **הנתונים נשמרים בדפדפן של המכשיר בלבד** ולא משותפים — זה מספיק כדי להתרשם, לא כדי להפעיל גמ"ח.

---

## שלב 1 — בסיס נתונים משותף (Supabase)

בלי זה, כל מתנדב יראה רק את מה שהוא עצמו הזין. עם זה, סימון של מוביל מופיע אצל הרכז תוך שנייה.

1. פתחו חשבון ב-[supabase.com](https://supabase.com) וצרו פרויקט חדש (השכבה החינמית מספיקה בקלות).
2. בפרויקט: **SQL Editor** → **New query** → הדביקו את כל התוכן של `supabase/schema.sql` → **Run**.
3. **Project Settings** → **API**, והעתיקו שני ערכים:
   - `Project URL`
   - `anon` `public` key

## שלב 2 — פריסה ל-Vercel

### דרך א׳: GitHub (מומלץ — כל `git push` מעדכן את האתר)

```bash
git init
git add .
git commit -m "גמח מזון"
git branch -M main
git remote add origin https://github.com/<המשתמש-שלך>/gemach-app.git
git push -u origin main
```

ואז ב-[vercel.com/new](https://vercel.com/new): **Import** את המאגר. Vercel מזהה Vite לבד ולא צריך לשנות הגדרות בנייה.

לפני `Deploy`, פתחו **Environment Variables** והוסיפו:

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | ה-Project URL משלב 1 |
| `VITE_SUPABASE_ANON_KEY` | מפתח ה-anon משלב 1 |
| `VITE_COORDINATOR_CODE` | קוד שתבחרו, למשל `1234` (אפשר להשאיר ריק) |

### דרך ב׳: שורת הפקודה

```bash
npm i -g vercel
vercel login
vercel link
vercel env add VITE_SUPABASE_URL production
vercel env add VITE_SUPABASE_ANON_KEY production
vercel env add VITE_COORDINATOR_CODE production
vercel --prod
```

> משתני סביבה נקראים **בזמן הבנייה**. אחרי שינוי שלהם צריך לבנות מחדש (`Redeploy` בממשק, או `vercel --prod`).

## שלב 3 — הכנסת הנתונים

1. פתחו את הכתובת שקיבלתם. אם הגדרתם `VITE_COORDINATOR_CODE`, לחצו על סמל המנעול והזינו אותו.
2. תפריט `…` → **ייבוא מהגיליון**.
3. בגיליון ב-Google Sheets סמנו את השורות (בלי הכותרת — היא תזוהה גם אם תיכלל), העתיקו, והדביקו.

סדר העמודות זהה לגיליון הקיים: מס׳ · שם · כתובת · טלפון · טלפון II · מקור · ת.הצטרפות · ת. הסרה. משפחה עם ת. הסרה נכנסת ישר לארכיון.

4. הוסיפו את המובילים במסך **מובילים**, קבעו לכל אחד כמה חבילות הוא לוקח, ולחצו **חלק אוטומטית**.
5. שלחו את הקישור למתנדבים. כל אחד בוחר את שמו בכניסה הראשונה.

## אבטחה — מה שחשוב שתדעו

`VITE_COORDINATOR_CODE` הוא **גדר נוחות, לא אבטחה**. הקוד נארז לתוך קובץ ה-JavaScript שהדפדפן מוריד, כך שמי שיטרח להסתכל בקוד המקור של הדף ימצא אותו. הוא מונע ממתנדב למחוק בטעות את רשימת המשפחות — לא יותר מזה.

באותו אופן, מדיניות ה-RLS ב-`schema.sql` פותחת קריאה וכתיבה לכל מי שמחזיק בקישור. לגמ"ח שכונתי שבו הקישור עובר בין אנשים מוכרים זה סביר ומקובל. אם אתם מחזיקים פרטים רגישים של משפחות ורוצים הגנה אמיתית, הדרך היא Supabase Auth: להפעיל התחברות במייל, להחליף את המדיניות כך שתדרוש `auth.role() = 'authenticated'`, ולהזמין רק את המתנדבים. זו עבודה של כמה שעות.

**אל תשימו לעולם** את מפתח ה-`service_role` של Supabase במשתני `VITE_*` — הוא עוקף את כל ההרשאות והוא יגיע לדפדפן.

## מבנה הפרויקט

```
src/
  types.ts                 טיפוסי הליבה + חוזה ה-Store
  lib/
    utils.ts               תאריכים, קישורי טלפון/ניווט, CSV, פענוח הדבקה
    localStore.ts          מימוש localStorage (מכשיר בודד)
    supabaseStore.ts       מימוש משותף עם realtime
    createStore.ts         בחירת אחסון + הרשאת רכז + זהות מוביל
    useGemach.ts           מצב, נתונים נגזרים וכל הפעולות
  components/
    ui.tsx                 אייקונים, גיליון מודאלי, שדות, קישורי קשר
    Shell.tsx              כותרת, ניווט תחתון, הודעות
    DeliveryRow.tsx        שורת משפחה — נגיעה אחת מסמנת מסירה
    Forms.tsx              טפסי משפחה ומוביל
  screens/
    Deliver.tsx            חלוקה שבועית (רכז)
    Families.tsx           ניהול משפחות
    Drivers.tsx            מובילים ושיבוץ
    MyRoute.tsx            המסך היחיד של המתנדב
    MoreMenu.tsx           ייבוא, מדבקות, ייצוא, דוח מקור
supabase/schema.sql        טבלאות, RLS, realtime, פונקציית סימון מסירה
```

החלפת בסיס נתונים לא נוגעת במסכים: מספיק לממש את הממשק `Store` מ-`src/types.ts` ולהחזיר אותו מ-`createStore()`.

## הערות

- **סימון מקביל**: שני מובילים שמסמנים באותה שנייה לא דורסים זה את זה — הסימון עובר דרך פונקציית SQL שממזגת שדה בודד ב-`jsonb`.
- **השבוע הנוכחי**: מזהה השבוע הוא תאריך יום ראשון. בכל יום ראשון בחצות האפליקציה עוברת לשבוע חדש והסימונים מתאפסים; הנתונים של שבועות קודמים נשמרים בטבלת `weeks`.
- **התקנה לנייד**: באנדרואיד Chrome יציע "הוספה למסך הבית". ב-iOS: שיתוף ← "הוספה למסך הבית".
